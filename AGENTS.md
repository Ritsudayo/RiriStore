# Правила проекта RiriStore

## Язык
- Все Markdown-документы, планы, статусы, файлы выполнения и отчёты пишите на русском языке.
- Имена файлов, команд, API, библиотек, переменных и функций не переводите.

## Источники истины
- `PRODUCT.md` — что и для кого строим.
- `PLAN.md` — план реализации, зависимости, риски и стратегия тестирования.
- `TASKS.md` — детали реализации, текущий статус и точный следующий шаг.
- `docs/agent/tasks/<TASK-ID>/` — отдельные timestamp-файлы каждой попытки выполнения.
- Git и тесты — фактическое состояние и доказательства.

## Перед работой
1. Прочитайте `PRODUCT.md`, `PLAN.md` и `TASKS.md`.
2. Найдите текущую задачу `IN_PROGRESS`.
3. Прочитайте последний файл выполнения, указанный в `TASKS.md`.
4. Проверьте `git status`, `git diff` и последние commits.
5. До изменения кода создайте новый файл:
   `docs/agent/tasks/T-XXX/YYYYMMDDTHHMMSSZ_<OWNER>_aNN.md`.
6. Сошлитесь на предыдущую попытку и продолжайте с поля `Точный следующий шаг`.

## Работа
- Одна небольшая проверяемая задача за итерацию.
- Не переписывайте несвязанные файлы и не добавляйте зависимости без одобрения.
- Каждый исполнитель обновляет только собственный timestamp-файл.
- Центральный `TASKS.md` изменяет один координатор после проверки diff и тестов.
- Не создавайте новый `PLAN.md`, если стратегия реализации и тестирования не изменилась.

## Перед завершением задачи
1. Запустите проверки: `npm run lint`, `npm run build`, `npx tsc --noEmit`.
2. Убедитесь что dev-сервер запускается (`npm run dev`).
3. Проверьте что миграции Prisma применяются без ошибок.
4. Запишите результаты в свой файл выполнения.
5. Обновите статус задачи в `TASKS.md` (только координатор).

## Стиль кода
- TypeScript strict mode.
- Компоненты React — функциональные, с хуками.
- Стили — Tailwind CSS (без CSS-модулей и styled-components).
- Все компоненты в `src/components/`, страницы в `src/app/`.
- Импорты через алиас `@/`.

## Безопасность
- Не выводите `.env`, токены, ключи, персональные данные.
- Не выполняйте `sudo`, `curl | bash`, массовое удаление без подтверждения.
- Пароли хэшируйте через bcrypt, никогда не храните в открытом виде.

## Создание задач
- Ты САМ создаёшь новую задачу T-XXX для каждого запроса пользователя.
- ID задачи = следующий по порядку (если последняя T-007, новая будет T-008).
- Перед началом работы:
  1. Определи ID новой задачи.
  2. Добавь новую строку в таблицу `TASKS.md` со статусом `IN_PROGRESS`.
  3. Создай файл `docs/agent/tasks/T-XXX/YYYYMMDDTHHMMSSZ_opencode_a01.md`.
  4. Только потом начинай работу.
- Не жди что пользователь скажет «создай T-XXX». Создавай сам.
- Если пользователь просит несколько вещей сразу — разбей на несколько задач T-XXX.
