# PRODUCT.md

## 1. Проблема и целевая аудитория

**Проблема**
Мастера ручной работы (украшения из бисера, браслеты, брелки) продают через Telegram-каналы и соцсети, но этот формат неудобен: нет каталога, нельзя положить товар в корзину, нельзя посмотреть историю заказов, сложно отслеживать заказы. Покупатели теряются в переписках, продавец тратит время на одни и те же вопросы.

**Целевая аудитория**
- **Продавец (RiriStore)**: мастер ручной работы, делает украшения из бисера и бусин, продаёт через Telegram, хочет автоматизировать продажи через сайт.
- **Покупатели**: девушки 16–30 лет, любят уникальные украшения ручной работы, заказывают через телефон, ценят удобство и красоту.

## 2. Основной пользовательский сценарий

1. Покупатель заходит на сайт → видит главную с баннером, категориями, новостями.
2. Открывает каталог → выбирает категорию (брелки, браслеты, чокеры, фенечки).
3. Кликает на товар → видит галерею фото, описание, цену, кнопку «В корзину».
4. Добавляет в корзину → открывает корзину → жмёт «Оформить заказ».
5. Заполняет форму (ФИО, телефон, адрес ПВЗ) → подтверждает заказ.
6. Заказ падает продавцу → продавец связывается и договаривается об оплате.
7. Покупатель регистрируется → видит свой заказ в профиле → может отслеживать статус.

## 3. Функции MVP

**Обязательный минимум:**
- Главная страница: баннер, инфо о магазине, категории, новости, соцсети.
- Каталог с фильтром по цене и пагинацией.
- Карточка товара: галерея фото, название, описание, цена, характеристики, избранное.
- Корзина: список товаров, изменение количества, удаление, итог.
- Оформление заказа: форма (ФИО, телефон, email, ПВЗ), выбор доставки (Яндекс/5Post).
- Регистрация и логин.
- Профиль: личные данные, аватар, мои заказы со статусами.
- Избранное.
- Админка: добавление/редактирование/удаление товаров и категорий, просмотр заказов.
- Управление объявлениями (блок новостей на главной).

**Не входит в MVP (потом):**
- Онлайн-оплата (первые заказы — вручную переводом).
- Интеграция с API доставки (только выбор ПВЗ текстом).
- Отзывы.
- Промокоды.
- Email-уведомления.
- Мобильное приложение.
- Сложная аналитика.

## 4. Проверяемые критерии готовности

- Пользователь может открыть главную, перейти в каталог, открыть карточку товара.
- Может добавить товар в корзину, оформить заказ, увидеть его в профиле.
- Может зарегистрироваться и войти.
- Может добавить товар в избранное.
- В админке можно добавить товар (с фото, названием, ценой, категорией) — он появляется в каталоге.
- В админке можно создать категорию — она появляется на главной.
- Все страницы работают на мобильном.
- Сайт задеплоен на Vercel и доступен по ссылке.

## 5. Технические и организационные ограничения

- Стек: Next.js 15 (App Router), TypeScript, Tailwind CSS, Prisma + SQLite (для разработки), NextAuth для авторизации.
- Хостинг: Vercel (бесплатный план).
- Оплата: на старте — вручную (перевод на карту/СБП), потом — ЮKassa (когда будет самозанятость).
- Доставка: Яндекс Маркет / 5Post (ПВЗ), трекинг по ссылке сервиса.
- Стиль дизайна: готика (викторианская/ведьминская, точно определим позже).
- Срок: без жёсткого дедлайна, итерациями.
- Команда: одна разработчица + ИИ-агент.

## 6. Риски продукта

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Мало покупателей | Высокое | Сайт сам трафик не даёт — нужна реклама в TikTok/Instagram/Pinterest, но это отдельная задача |
| Сложно с оплатой (нет самозанятости) | Среднее | На старте — перевод вручную |
| Стиль «готика» может отпугнуть | Среднее | Не перебарщивать, использовать тёплые тона, не пугать |
| Долгая разработка | Среднее | Итерациями, MVP первым, дизайн потом |
| Мало товаров | Низкое | Начать с 6-10, расширять ассортимент |
